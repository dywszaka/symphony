# Symphony Phoenix Phase 4 Design

## Goal

Add the Codex-backed agent runner required by `SPEC.md`: render per-issue prompts, launch
`codex app-server` in the issue workspace, drive a thread/turn lifecycle over stdio JSON-RPC, and
expose a runner module the orchestrator can spawn.

## Scope

- Strict prompt rendering for `{{ issue.* }}` and `{{ attempt }}` values.
- Minimal Liquid-compatible interpolation with explicit errors for unknown variables and filters.
- Codex app-server client for the current v2 protocol generated by
  `codex app-server generate-json-schema`.
- `initialize`, `thread/start`, and `turn/start` request/response handling.
- Line-delimited JSON-RPC over stdio, launched through `bash -lc <codex.command>` in the workspace.
- Turn completion, failed/cancelled, read timeout, turn timeout, and malformed JSON handling.
- High-trust policy documented in code/tests: command and file-change approvals are accepted for the
  session; user-input requests fail the turn instead of stalling.
- Runner module that creates/reuses per-issue workspace, renders the first prompt, sends continuation
  prompts while the issue remains active, refreshes tracker state between turns, and respects
  `agent.max_turns`.

## Out of Scope

- `linear_graphql` dynamic tool implementation.
- Live Codex smoke tests against a real authenticated account.
- Token/rate-limit aggregation in orchestrator snapshots.
- Dynamic workflow reload and hook execution.

## Protocol Notes

The local schema generated on 2026-05-14 shows:

- `initialize` requires `clientInfo`.
- `thread/start` accepts `cwd`, `approvalPolicy`, `sandbox`, `ephemeral`, and service metadata.
- `turn/start` requires `threadId` and `input`, where text input is
  `%{"type" => "text", "text" => prompt}`.
- `thread/start` response returns `thread.id`.
- `turn/start` response returns `turn.id`.
- `thread/tokenUsage/updated` and `account/rateLimits/updated` notifications are passed through as
  raw runtime events for later aggregation.

## Testing

All tests use fake app-server scripts or fake app-server modules. No test starts a live Codex
session.
